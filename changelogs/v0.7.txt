Endless 0.7

- Added explicit Create compatibility for Forge 1.20.1 / Create 6.0.8 and NeoForge 1.21.1 / Create 6.0.11.
- Fixed Create schematic rail placement at sparse Y by routing its dense-section write through Endless sparse storage while preserving Create's block update semantics.
- Fixed Create kinetic generator network-ID aliasing above the packed BlockPos Y range. Sparse generators now receive collision-free per-dimension IDs from persistent SavedData, survive unload/reload and cold restart, and rebuild old packed-ID networks through Create's detach/setNetwork/attach lifecycle, including late-loaded followers.
- Preserved exact high-Y positions for Create display-link reservations and redstone-link relocation state instead of relying only on BlockPos.asLong().
- Fixed Create mechanical-arm and weighted-ejector client hover caches so positions separated by a packed-Y alias period are not treated as the same target. The ejector cache follows the effective placement cell (including the hit face), wrench mode, and world/reset changes.
- Audited Create contraption serialization: block positions are serialized in local contraption space and the default 2,048-block assembly cap keeps those local coordinates inside BlockPos's packed-Y range, so no Endless hook is applied there.
- Audited Create/Flywheel SectionPos visual caches: Minecraft's 20-bit packed section Y covers the entire Endless +/-8,000,000 representation envelope, so their key width alone does not require rewriting. This is not a proof of complete lighting, culling, or cache-lifetime correctness.
- Extended the real-client matrix with Create sparse-placement/kinetic coverage and a cold-restart persistence/migration gate with an independent missing-allocator negative control on both supported Create loader lines.
- Refuse invalid/unreadable existing Create allocator files outside SavedData's catch-and-reset boundary. Validate record types and preserve corrupt files for recovery instead of reusing IDs.
- Separate cold-restart identity persistence from legacy migration: retain synthetic IDs in saved block entities, compare against an independent phase-A checkpoint, and require deletion of the allocator to fail that regression before restoring the original test world.
- Added real connected-network legacy-NBT fixtures in root-first, follower-first, and late-follower load orders, checking two generators, a mechanical press, common network-object membership, exact stress/capacity totals, overstress, and recovery. Disk-backed allocator corruption probes run through the supported loader storage boundary.
- Keep ordinary live-test clients connected after their local PASS until all required server/client evidence is collected. Disconnects before completion fail explicitly rather than stalling the server fixture.
- Documented the 29-cell live gate, allocator backup/recovery requirements, and limits of development launches and source-backed client-cache coverage. Version 0.7 remains the pending release; no historical release is rewritten.
