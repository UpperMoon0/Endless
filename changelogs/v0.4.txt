Endless v0.4 — Engine trust fixes

This release fixes correctness bugs found in review and caps the supported
build range to what the game's packed coordinates can actually represent.

Behavior changes:
- Build height is now capped to vanilla's guarded packed BlockPos envelope:
  min >= -2032, max <= 2032 (exclusive top, highest placeable Y = 2031).
  Previously advertised ±2,097,152 was not representable — packed positions
  and block-update packets silently wrapped beyond the envelope. The 16-block
  guard band at each edge (exactly vanilla's DimensionType span) keeps
  neighboring-block operations like BlockPos.offset and light propagation
  from wrapping into the opposite end of the world.
- The build range is persisted per world (data/endless_build_heights.dat in
  the world root). It is read before any level is created, so chunk
  deserialization always uses the world's range; the effective range is the
  union of the world's stored range and the config: widening the config
  expands the world, narrowing is rejected with a log warning so saved
  chunks above/below the new bounds can never be silently dropped.
- Multiplayer servers are authoritative: the build range is sent to every
  client as the first play packet of the join, before the login packet and
  any chunk packet. Chunk packets carry no Y coordinates per section, so a
  mismatched client previously could map section payloads to the wrong Y
  positions. Clients without the mod are disconnected with a clear message
  when the server's range is extended; they can still join vanilla-range
  servers. The sync packet is registered strictly server-to-client on Forge
  and validated on receipt, so a spoofed client packet cannot change the
  server's range.
- Chunk sections are no longer left null outside the world-generation range.
  All sections in the configured range are real sections, matching vanilla
  invariants for saving, networking, lighting, and mod integrations.
- Height values are normalized to 16-block section boundaries on load.
- Config changes that produce an invalid range reset to vanilla defaults.
- Malformed config files no longer risk breaking startup: parse errors fall
  back to defaults. When the original can be copied to endless.json.broken it
  is overwritten with defaults; if the backup fails, defaults apply in memory
  only and the original file is left untouched.

Fixes:
- Custom ChunkAccess section helpers (isYSpaceEmpty mask, highest-filled
  scan, findBlocks) were removed; vanilla logic runs unchanged.
- Vanilla lighting storage semantics restored: the synthetic dark-layer and
  copy-on-write overrides were removed, so missing light sections stay null
  exactly as vanilla expects.
- The below-zero retrogen accessor was left untouched: the old override
  pointed vanilla's legacy chunk migration machinery at the mod's extended
  range, which could shift upgraded generation into an unrelated Y band.
- The heightmap mixin was removed; vanilla sizes and stores heightmaps from
  the effective chunk height, which the mod already provides.
- The global SimpleBitStorage error suppression was removed: invalid heightmap
  writes are caught by the heightmap fix instead of being silently discarded
  everywhere.
- The periodic section cleanup no longer loads or generates chunks (the
  synchronous 7x7 getChunk(..., create=true) scan around every player was
  removed together with the null-section purge it existed to serve).
- The client render grid is now a window that follows the camera vertically
  (32 sections, rebased with hysteresis) instead of a fixed slab anchored at
  minBuildHeight.
- Initialization is idempotent across Fabric mod/client/server entry points
  and Forge common/client setup.
- README no longer contradicts the implementation (exclusive maxBuildHeight,
  real section counts, correct repository URL).

Developer:
- Added a PR validation workflow (build + tests on every pull request and
  non-master push), ahead of the existing release workflow.

Known limitations:
- True heights beyond the guarded packed-Y envelope would require replacing
  Minecraft's position serialization itself; that is out of scope for this
  release.
- Vanilla clients (without Endless) are disconnected from servers with an
  extended range; keep vanilla clients on vanilla-range servers.
- Free-camera mods can move the camera while the player stays in the same
  section; the render window then follows the camera only on the next
  vanilla-triggered update.
